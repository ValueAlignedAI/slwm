# G5C structure and scale

Registered after both G5 development screens. Neither the 192-update nor the 2,048-update small-model comparison surpassed zero displacement on the simulator. No novel test target was used to choose this experiment.

Test whether the shared representation learns predictable information left over after fitting simple physical priors. Fit a separate ridge model of block displacement at each of the 16 horizons from training scenes. Each prior uses only history and controls scheduled through the corresponding horizon. Fit increasing logistic contact odds from training-only frame motion. Both architectures receive the same priors, targets and optimization. The learned correction for each task is a function of the shared 128-dimensional state. These fixed priors form an explicit task-specific bypass. A combined-model score is evidence for the learned shared state only to the extent that it improves on the identical prior by itself. The eight other source types or families never supply calibration examples for these priors.

Start both 8-layer width-512 cores from scratch at batch 128, with seeds 511 and 512 and 4,096 updates each. Give both signed causal motion cues and block-relative actions when the physical state is observed. Initialize both residual readouts to zero. Keep the nine-family training mixture. This comparison tests the combined model at scale. It cannot isolate scale from the physical priors using G5B alone.

Advance to the width-896, 12-layer, 8,192-update anchor only if at least one architecture improves on both trained priors on average across both development seeds, by at least 1% relative on each endpoint. Both architectures advance together. The original two-seed, two-endpoint, 5% architecture and uncertainty criterion remains the public win condition. Evaluate independent novel dates and scenes only once at the terminal locked scale, after the weight and optimizer archives are verified. Retain the prior-only, erased, shifted and unplanned controls. If a new device cannot be allocated, record its actual status and continue on the 3090. GPU and TPU endpoints have distinct run names.
