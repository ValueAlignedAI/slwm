# Operational follow-up after the first G8 rollouts

The initial live controllers and the first-proposal heuristic frequently moved the object farther from the goal. The three registered proposals all contain motion. On **new starts** test whether a perfect one-decision predictor can operate this proposal bank, and whether adding a hold option changes the result. This diagnostic was chosen after seeing the initial live failures. It does not replace the registered model comparison.

Use 64 starts numbered 1160000–1160063 for Push-T and 1170000–1170063 for the puck task. Pair goal, initial configuration and per-start proposal randomness. Run 24 decisions of 16 actual ticks. Compare the issued first proposal and passive control, an exact greedy oracle over the original three proposals, and an exact greedy oracle over the same three plus holding the current pusher position. At each choice, reconstruct the simulator from the original seed and all previously issued controls, execute each alternative, and minimize its actual distance at the end of the next 16 ticks. Recheck the executed branch against the oracle's measured endpoint. Report final success within 20 px, final distance, ever reaching the goal and the paired difference between the two oracle policies. These are greedy physical controls; they do not bound the best possible multi-decision plan.
